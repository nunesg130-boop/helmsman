# Self-test (v1.17.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Helmsman asks its own agent a batch of questions generated from the live lab, saves each answer as a conversation, and shows a review page where the owner rates or fixes them for fine-tuning.

**Architecture:** A pure generator (`server/selftest-questions.mjs`) builds questions from the monitor snapshot. A runner (`server/selftest.mjs`) feeds them one at a time through a new read-only internal ask path in `server/agent.mjs`, keeping its queue in `/data/selftest.json`. Conversations carry a `selfTest` marker. New routes under `/api/v2/agent/selftest` and a "Self-test" card in the Agent settings reuse the existing rating route and "Download good and fixed".

**Tech Stack:** Node ESM (`node --test`, no new dependencies), the single-file browser app `src/app-v5.js`.

**Spec:** `docs/superpowers/specs/2026-10-30-self-test-design.md`

## Global Constraints

- Batch size 1 to 500, default 50. Review page size 25. Asked-ID cap 20,000 (oldest dropped first).
- Question text is plain text, at most 1,000 characters (`MAX_QUESTION_CHARS`).
- The runner passes `allowProposals: false`; it never creates, approves or runs an action.
- `/data/selftest.json`: mode 0600, atomic write, revision-checked like `server/manual.mjs`, no credentials.
- All new routes need the owner session, CSRF on non-GET, and the existing origin binding (they sit inside `handleApi`, which `agentApi` already guards).
- No new dependencies. Existing export format and `prepare_data.py` input stay unchanged.
- Version files move from 1.16.9 to 1.17.0, including regex-escaped forms (`1\.16\.9`, `1[.]16[.]9`) in `scripts/`.
- Commit messages and the PR end with the attribution lines the session was given.

## Review Focus

- Empty inventory or no snapshot yet: `start` refuses with "Helmsman has no inventory yet." and generates nothing.
- Names with quotes, spaces, `|` or very long text (container and guest names are owner data): questions stay under 1,000 characters and contain no control characters.
- Two guests with the same name (VM 109 and VM 201 are both "docker"): the generator asks by VMID as well as by name, and IDs differ.
- Stop pressed while a question is in flight, then Helmsman restarts: the run shows "paused (restart)", the half-asked question is asked again, and nothing is recorded twice.
- "Keep conversations for training" off, or the model server unreachable three times: the run stops with a reason instead of looping or silently doing nothing.

### Task 4: Runner, state file and review listing

**Files:**
- Create: `server/selftest.mjs`
- Test: `tests/selftest.test.mjs`

**Interfaces:**
- Produces: `createSelfTest({ dataDir, askSelfTest, snapshot, conversationStore, conversationsKept, clock = Date.now, guard = async () => {}, seed = () => Date.now() }) -> Promise<{ start({count}), stop(), continueRun(), status(), review({ filter, category, cursor }) }>`.
  - `status()` returns `{ running, paused, reason, queued, done, failed, unrated, categories, asked }`.
  - `review()` returns `{ items: Array<{ conversationId, question, answer, toolsUsed, category, rating, correction, changedFromBefore, failed }>, next: string|null }`, 25 per page; `filter` is `"unrated"` (default), `"all"`, `"changed"` or `"failed"`.
  - Errors are `SelfTestError(status, code, message)` with codes `SELFTEST_NO_INVENTORY` (409), `SELFTEST_KEEP_OFF` (409), `SELFTEST_BAD_COUNT` (400), `SELFTEST_RUNNING` (409).
- Consumes: Task 2 `generateQuestions`, Task 3 `askSelfTest`.

- [ ] **Step 1: Write the failing tests** in `tests/selftest.test.mjs` with a fake `askSelfTest`, an in-memory snapshot (`labSnapshot()`), and a temp `dataDir`:
  - `start asks count questions in order and records ids as asked`.
  - `a follow-up is asked with the previous question and answer as history`.
  - `stop finishes the question in flight and then halts` (status `running:false`, remaining questions still queued).
  - `a restart shows paused (restart) and continue re-asks the interrupted question once`.
  - `AGENT_BUSY waits and then carries on` (fake rejects once with `AGENT_BUSY`; fake timers or an injected `sleep`; the question is eventually answered exactly once).
  - `three consecutive model failures stop the run with a reason` (`reason` mentions the model server).
  - `a single failed question is recorded as failed and the run continues`.
  - `start is refused with SELFTEST_KEEP_OFF when conversations are not kept`, `SELFTEST_NO_INVENTORY` when the snapshot is empty, `SELFTEST_BAD_COUNT` for 0 and 501, `SELFTEST_RUNNING` while running.
  - `the second batch never repeats an asked question id` and `asked ids are capped at 20,000, oldest dropped`.
  - `selftest.json is mode 0600 and holds no answers`.
  - `review lists unrated first, pages 25 at a time, and flags changedFromBefore when the same question id has a different earlier answer`.
- [ ] **Step 2: Run** `node --test tests/selftest.test.mjs`. Expected: FAIL (module missing).
- [ ] **Step 3: Implement** `createSelfTest` and `SelfTestError`. Persist `{ version: 1, asked: [ids], queue: [questions], current, counts, revision, updatedAt }` with the atomic-write and revision pattern from `server/manual.mjs`. One loop at a time, guarded by a flag; a loaded state with a non-empty queue starts as `paused` with reason `"restart"`. Link each answer to its question id through the conversation's `selfTest.id` (review reads `conversationStore.list({ selfTest: "only" })`), so no answer text is stored in `selftest.json`.
